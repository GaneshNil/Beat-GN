# Physical test checklist for Marv Neo V006213

Record phone model, Android version/API, app build SHA-256, watch model, exact firmware, timezone, and date/time. Keep the full address and health measurements in local notes. Use the address suffix and sample identifiers in shared reports.

## Installation and identity

1. Run `adb devices -l`. For a USB phone, enable USB debugging and approve the phone’s authorization dialog. Check that the device shows as `device` before proceeding.
2. Install the debug APK with `adb install -r app/build/outputs/apk/debug/app-debug.apk`. For the app-upgrade scenario, use a test handset with a previous build signed by the same key and a backup or synthetic records. If Android reports a signature mismatch, use the matching signing key or a separate test profile.
3. On the watch, open Settings → About (menu wording may vary) and check the model plus `V006213`. In Beat-GN, after connecting, check More → Device information. Compare any reported GATT values with the watch. Record which of `2A24`, `2A26`, `2A28` and `2A29` were absent.
4. Close the vendor app’s active BLE session before testing Beat-GN alone. Keep the vendor app available for baseline comparisons. The watch calling Bluetooth profile is a separate pairing flow.

## Test cases

| Case | Action | Expected evidence and common failure symptom |
| --- | --- | --- |
| Permissions | Deny Nearby devices on Android 12+ or precise Location on Android 11. Test the Watch permission button, grant via prompt or Settings. Deny notification permission separately on Android 13+. | No crash, clear recovery path, discovery after granting access, and continued connection eligibility after notification denial. Android 11 with system Location off should show the Location instruction. |
| Scan and selection | Scan, stop, rescan and choose the target. Compare address suffix with the watch. Try an unrelated named BLE device if one is safe to select. | Scan ends cleanly, candidate selection remains manual, and connectable rows advertising FEEA appear first. Unrelated profiles are rejected after discovery. An advertisement can omit FEEA, so a known watch row is still selectable. If the watch advertises under a different name/address, select the newly seen row rather than edit the known MAC. |
| GATT and battery | Connect, check FEEA discovery and CCCD status in diagnostics, then use Read battery. Compare phone and watch battery. Inspect More for MTU and identity. | Ready follows a valid watch Battery Level read. On failure record service presence, characteristic properties, CCCD status or timeout, MTU, and battery callback status. A write status alone does not establish the link. |
| Time | Set the test phone to automatic date/time in Asia/Kolkata. Reconnect and compare both displays at the minute rollover. Repeat in a whole-hour-offset test zone and across a DST change where practical. | Watch time is correct and remains correct after reconnect. Report any 30-minute mismatch and both local zone settings without changing command bytes speculatively. |
| Pulse | Wear the watch correctly, start Pulse, compare the actual watch reading with the app and Health report. Repeat with no skin contact, navigate away during a request, and disconnect mid-measurement. | Valid `2A37` data updates app and local report. `0x6D` status alone yields no BPM. Missing data times out, and link loss terminates the request. |
| SpO₂ | Start Oxygen under stable conditions. Repeat with no reading and with a rapid tab switch. | A valid watch reply yields a displayed and stored result. Silence times out. Rapid taps send no duplicate start for an active request. |
| Blood pressure | Run BP probe while the watch is properly worn. Compare any actual result to the watch UI. Repeat during a normal connection and after an interruption. | Only a valid pressure pair is stored. A timeout, including repeated timeouts, does not establish unsupported hardware. Record whether DaFit offers BP on the same firmware. |
| Activity | Walk a counted series of steps and check watch versus app. Compare distance, calories and active minutes when reported. Repeat across midnight and reconnect. | Zero appears as zero, missing values stay blank, and Room retains the values present in each partial snapshot. Check the units and whether counts are cumulative for the watch day. |
| Alarms | Save offline, restart app, reconnect and Send to watch. On the watch check the slot, time, repeat days and enabled state; schedule a nearby alarm and observe the physical alert. Repeat edit and disable. Test all slots and a phone-only deletion in a disposable slot. | Local settings survive restart. Android write is reported as Sent, and actual watch scheduling is recorded separately. Confirm whether deletion left the watch alarm; remove it on the watch if necessary. |
| Find watch | Press Vibrate watch with watch nearby, then test after disconnect. Observe vibration directly. | Callback can mark the write as completed. The test passes only with an observed alert. Capture whether the watch UI or current mode suppresses alerts. |
| Reconnect | Turn Bluetooth off/on, leave range, return, then explicitly disconnect and relaunch. Repeat while a command is queued. | Automatic reconnect stays bounded, no stale battery or health values display, and intentional disconnect survives Bluetooth toggles and relaunch. Manual rescan recovers changed addresses. |
| Background | Leave Beat-GN in background and screen off for 15–30 minutes with the watch nearby. Test with default and manually changed OS battery settings and check the ongoing notification where allowed. | Record whether battery or telemetry reads continue and whether the app recovers on foreground. Note OEM power policy and elapsed time if the OS suspends the service. |
| History and reports | Collect watch measurements while disconnected, then connect. Compare with a local live recording, report window changes, app restart, and a timezone change. | Locally received records persist and group by current local calendar days. Device history backfill is absent. A timezone change or midnight rollover updates the report without requiring a new watch reading. |
| UI and accessibility | Test Home, Health, Watch, Assistant and More in light/dark themes, small portrait and landscape layouts, and large fonts. Use TalkBack and Android Back. | Measurement buttons wrap, chart cells have date/value descriptions, alarm validation is readable, deletion confirms its phone scope, and More navigation returns correctly. Compare legacy transcript badges if present. |
| Room upgrade | Run `./gradlew connectedDebugAndroidTest` on a phone or emulator. Also check upgrade from a same-signature build with a seeded prior database. | Room opens the legacy database and preserves health data. Test alarms persist across reopen. Keep test results separate from the BLE results. |

## Capture

- Open More → Diagnostics and tap Copy after the attempt. For a missing FEEA failure, retain the service inventory, characteristic properties and CCCD presence alongside the selected address suffix. For app-only log collection run `adb logcat -d -s WatchBleManager:D WatchCompanionService:W MainActivity:W`. Share timestamps, GATT statuses, characteristic IDs, opcodes and packet lengths.
- For unresolved firmware behavior, collect a controlled Android Bluetooth HCI snoop session if the owner approves local capture. It can include the full address and private payloads. Keep the raw file private, capture only the relevant action, and redact identifiers and health bytes before sharing any excerpt.
- Record pass or fail based on watch observations or read-back. If a device, permission, baseline data or verified firmware is missing, mark the case **BLOCKED** and state which prerequisite was missing.
