# Beat-GN final audit

## Assessment

Beat-GN is a local-first Android companion for the beatXP Marv Neo. The audit started from `004da9d3` on `main`, independently reproduced two regressions on the baseline, and repaired confirmed transport, health-storage, alarm and UI defects. The build and local automated tests support handing the APK to a device tester. Release acceptance depends on observing the target watch and testing Android lifecycle and migration behavior.

The supplied firmware is V006213. No phone or emulator was visible to ADB. The cited vendor APK was absent from its historical location and accessible local file inventory. None of the V006213 capabilities were physically confirmed. Product documentation and previous SDK findings identify what to test. [Firmware report](MARV_NEO_V006213_COMPATIBILITY.md) · [Verification matrix](FEATURE_VERIFICATION_MATRIX.md)

## Android 16 field follow-up

The startup regression came from Compose lifecycle-owner lookup. Providing the Activity's lifecycle owner restored rendering in the Android 16 emulator and in the owner's subsequent screenshot. The screenshot also showed a missing FEEA error after attempting a watch connection. The 1.1.3 repair improves scan selection, GATT profile validation and diagnostics. The phone was unavailable through ADB and the host BLE scan found no matching watch, so the endpoint that caused the error and end-to-end firmware behavior remain open. [Firmware report](MARV_NEO_V006213_COMPATIBILITY.md)

This pass also corrected firmware and software labels, late measurement callbacks, partial activity persistence, explicit heart-rate contact-loss handling, failed alarm writes, and transcript deletion across navigation. Android coverage exercises launch and screen navigation, Room upgrade and GATT profile selection using synthetic service inventories. [Change log](BUG_FIX_CHANGELOG.md) · [Test results](TEST_RESULTS.md)

## Architecture and feature inventory

| Layer | Current implementation |
| --- | --- |
| Android entry and navigation | `MarvNeoApp` owns one process-scoped dependency graph. `MainActivity` handles permissions and five Compose destinations. More has device, diagnostics, software and About pages. |
| Bluetooth | `MarvNeoBleManager` owns scan selection, the selected/verified reconnect target, session state, pending callbacks, subscriptions, telemetry and outgoing commands. `GattOperations` serializes individual requests. `CrrepaProtocol` and `CrrepaFrameAssembler` implement previously documented family framing. |
| Background | `WatchCompanionService` mirrors connection state in a connected-device foreground notification and handles the protected Bluetooth state broadcast. Service loss closes the session. |
| Storage | Room version 5, seven entities. The DAO stores steps, pulse, oxygen, pressure, sleep, alarms and voice rows. `MigrationSql` upgrades versions 1–4 and preserves activity data. Sleep storage currently has no BLE producer. |
| Telemetry and reports | The Home dashboard shows watch and live activity data plus today’s local health averages. Health provides measurement commands, calendar periods, aggregate statistics and pulse history. Direct device history backfill is absent. |
| Watch controls | Scan, choose, cancel, reconnect, disconnect, battery read, Find watch and an alarm editor. Time sync is sent once when a link becomes verified. Alarm deletion is local. |
| Assistant and More | Assistant presents stored rows with provenance and clear-history confirmation. No active watch transcript producer exists. More presents optional device identifiers and metadata-only Bluetooth diagnostics. |
| Verification | JVM tests cover protocol byte layouts, fragmentation, GATT queue behavior, measurement transitions, storage, schedules and reports. The Android test APK contains a Room migration/reopen test. |

## Confirmed defects and repair evidence

| Area | Baseline defect and root cause | Repair and verification |
| --- | --- | --- |
| Connection and callbacks | `runGattOp` used one anonymous deferred. Late callbacks could satisfy a later request. The GATT handle was captured before waiting for the mutex, and initialization/recovery work could run on a replacement session. | Guard all request starts and completions by the owning link and match callback kind and attribute. Close ambiguous sessions after a dropped non-MTU callback. JVM queue tests cover stale, false, timeout, revoked-start equivalent, and cancellation paths. |
| Scanning and retry | A shared scan callback could publish results or failure after a scan ended. Scan ignored unnamed advertisers and auto-connect could pick an unrelated bonded device from a name heuristic. A Bluetooth toggle cleared deliberate disconnect, and successful foreground starts could restart automatic retry. | Give each scan its own callback and retain manual selection. Save the verified address and explicit disconnect preference. Test five bounded delays in the JVM and validate the Android lifecycle on device. |
| Permissions and service | Initial and foreground access paths overlapped. The Watch UI gave little recovery after denial. The non-exported runtime receiver could miss broadcasts from the privileged Bluetooth process. | Add an explicit permission recovery action, guard service startup and listen to the protected adapter action. Removed unused wake-lock and direct battery-exemption permissions. [Android broadcast guidance](https://developer.android.com/develop/background-work/background-tasks/broadcasts) |
| Protocol | The direct parser accepted invalid versions despite reassembly rejecting them. The active write path always used `0x10` despite larger negotiated ATT chunks documented in SDK evidence. | Reproduced the parser mismatch before fixing it. Test the documented version rule and MTU boundary. Verify outgoing firmware framing on the watch. |
| Measurements | Fast notifications could complete a measurement before its start callback and be overwritten. Explicit disconnection did not reset every active measurement. BP silence became “unsupported.” | Make requests process-owned, preserve a newer completion or failure, suppress another tap for an active request and clear session-scoped readings on link loss. Report a timeout as a timeout. |
| Activity | Missing distance became “0.00 km” when only steps arrived. True zeros were hidden and only step count governed persistence. | Track missing fields explicitly, display supported live fields, save partial and complete snapshots and dedupe per local day. Retest partial packets, all-FF, zero and rollover. |
| Reports and storage | Concurrent duplicate checks could both pass. Interleaved duplicates evaded the report pass, while samples around midnight could suppress a new day’s first data. Report zone was captured for the life of the repository. | Reproduced duplicate inserts. Serialize the write transactions in the process, scope duplicates to local calendar days, refresh active reports on day/zone changes and recompute after returning to the app. Preserve timestamped records and Room schema identity. |
| Alarms | Invalid text was silently clamped, empty enabled schedules were accepted, and transmission updates could be cancelled by leaving the Watch tab. A single Pending label conflated operations. | Validate times and repeat masks, serialize save/send/delete, check current records and allocate at save. Save Pending/Sent/Failed based on storage and write outcomes. The watch remains the source for actual schedule verification. |
| UI truth and accessibility | Chart labels were clipped in narrow cells. Three measurement controls could overrun a row, delete lacked a label, and history copy implied automatic watch history. Upgraded Assistant rows could be presented as watch replies. | Use lifecycle-aware collection, wrapping controls, horizontally scrollable date-labelled charts, restorable navigation/forms and explicit delete labels. Identify legacy entries and explain unavailable backfill. Device rendering remains blocked. |
| Privacy | Logs included raw notifications, telemetry and exception details. Android’s device transfer can disregard `allowBackup=false` on some OEMs. | Emit transport metadata only. Mask address displays, remove unused permissions and explicitly exclude the Room database and preferences from cloud backup and device transfer. [Android backup behavior and rules](https://developer.android.com/identity/data/autobackup) |

## Security and build review

- The merged app manifest has no internet, microphone, notification listener, or raw storage permission. The app’s launcher is public, the watch service is private, and the merged AndroidX debug profiling receiver requires Android’s `DUMP` permission. Direct BLE frames are length/version checked and characteristic-scoped. The expected profile and battery read establish liveness. They cannot authenticate hardware that imitates the profile.
- Room queries use bound parameters. Room version 5 migrates activity rows with their IDs and leaves unrecorded fields empty. The committed Room schemas track the change. Device extraction rules protect the database and watch preferences from normal Android backup/transfer paths. Existing records generated by much older app versions may have unknown provenance.
- AGP 8.6.1 has Android SDK 35 support and works with the existing Gradle 8.7 and JDK 17. The test-only SQLite JDBC dependency moved from 3.45.3.0 to 3.54.1.0 to pick up upstream fixes. An OSV batch query returned zero matches for 87 resolved release runtime Maven coordinates. That scope excludes the Android OS and build/test tooling. [AGP 8.6 release notes](https://developer.android.com/build/releases/agp-8-6-0-release-notes) · [SQLite vulnerability notes](https://www.sqlite.org/cves.html) · [SQLite JDBC releases](https://github.com/xerial/sqlite-jdbc/releases) · [OSV API](https://google.github.io/osv.dev/api/)
- The second pass traced the Activity/Compose controls through service events, BLE callbacks and DAOs, checked the merged manifest and schema, and reviewed the working-tree diff. The build and lint output, counts and runtime blockers are recorded separately. [Test results](TEST_RESULTS.md)

## Open and unconfirmed issues

- The exact V006213 profile, bond requirements, Android scan filtering, MTU and frame version choice, characteristic write properties and write/notify timing all need an attached watch. Missing standard Battery Level data leaves a compatible-looking session Unstable.
- The request/notification protocol used here has no measurement ID. A late valid notification can still be indistinguishable from another reading of the same kind. A checksum-free frame with a plausible but damaged length can consume subsequent bytes. Changing retransmission or resynchronization rules requires representative captures.
- A time-sync frame contains a whole-hour UTC offset. Check Asia/Kolkata and DST behavior on the watch. Validate actual activity units/reset behavior and BP status codes before treating them as device guarantees.
- Watch alarm read-back/deletion, dated alarms, history import, sleep and notification controls remain investigation items. OS background behavior, live Compose interaction, backup and Room framework migration need a device or emulator. No signed release or benchmark was run.
